# Проверки после аудита

Проверки выполнены на Ruby 4.0.6 / Rails 8.1.3.1 с версиями зависимостей из существующего Gemfile.lock. Зависимости проекта не обновлялись. Rails запускался в отдельном Docker-контейнере; storage, tmp и log находились в tmpfs. Рабочие базы пользователя и production не подключались.

- `bin/rails test`: 95 тестов, 494 проверки, ошибок и пропусков нет.
- `bin/rails test:system`: 3 браузерных теста, 19 проверок, ошибок и пропусков нет. Проверены мобильное сохранение/редактирование прогноза, ввод голов через Stimulus, предпросмотр/подтверждение результата и регистрация service worker. Браузер — Chromium 156 с отдельным временным профилем; для удалённого тестового браузера предусмотрены SELENIUM_REMOTE_URL, CAPYBARA_APP_HOST и BROWSER_BINARY.
- `bin/rails zeitwerk:check`: успешно. Стандартное предупреждение о test/mailers/previews, не включённом в eager_load_paths, не препятствует загрузке приложения.
- RuboCop для 46 изменённых и новых Ruby-файлов: нарушений нет. Полный первоначальный запуск выявил также замечания в старых неизменённых файлах, включая применённую миграцию; эта миграция не переписывалась. Это не утверждение о полностью зелёном CI всего репозитория.
- `bundle exec brakeman --quiet --no-pager`: 0 ошибок и 0 предупреждений безопасности. Обёртка `bin/brakeman` дополнительно требует последнюю версию анализатора; установленная по lockfile версия 8.0.6 не последняя. Проверки кода выполнены установленной версией, зависимости для обхода этого требования не менялись.
- Production `assets:precompile` с APP_HOST=assets.invalid и SECRET_KEY_BASE_DUMMY=1: успешно. libvips отсутствует в тестовом Ruby-контейнере, поэтому выводится предупреждение для преобразования изображений; production Dockerfile уже устанавливает libvips.
- ERB/YAML конфигурация Kamal проверена с фиктивными параметрами, HTTPS и постоянным томом. Соединения с VPS, создание сервера и деплой не выполнялись.
- SQLite Online Backup / восстановление проверены отдельным тестом с WAL и проверкой запрета перезаписи существующего каталога.
- `git diff --check`: успешно. Применённые миграции и Gemfile/Gemfile.lock не изменялись; добавлена одна новая миграция с двумя nullable-полями.

В тестах покрыты права административных действий, импорт, обязательная смена legacy-пароля, границы окна, лимиты игроков и ставки, параллельное резервирование/подтверждение/выдача наград, все уровни тай-брейка матча, разные переходы Топ-10, откат нескольких матчей, версии правил, приватность HTML/JSON, неизменность ответов choice и сохранение архивированных ачивок.

Перед обновлением локальной базы выполните резервное копирование и новую миграцию по [инструкции](DEPLOYMENT.md). Исторические правила старых подтверждений без снимка восстановить автоматически невозможно. Откат, который оставил бы необеспеченные ставки, полностью отменяется с понятной причиной.
